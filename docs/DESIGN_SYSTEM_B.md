## 1. Design Read

```yaml
artifact:          工具型 Web 应用（表单 + 数据密集的行程详情 + 运维控制台）
audience:          自助旅行者（中文），桌面为主、手机必用
visual-language:   杂志编辑 —— 白纸底、色块分区、粗黑线、超大号数字、反转块
mode:              redesign · overhaul（保留信息架构与功能契约，重写视觉层）
visual-variance:   6    （版面靠色块与粗细对比造节奏，比上一版更有张力）
motion-intensity:  3    （干脆的短动效，无弹跳、无持续动画）
information-density: 6  （数字与标签信息密度提高，正文保持宽松）
asset-dependence:  7    （旅行照片仍是核心资产，但版面本身已有足够表现力）
brand-fidelity:    3    （无既有 logo 与品牌规范，品牌色从零定义）
```

### 四条核心手法

1. **色块分区** —— 用实色块切分版面，而不是给每块套卡片
2. **粗黑线** —— 2px 黑线承担分隔与强调；层次由线与色块建立，不用阴影
3. **超大号数字** —— 天数、序号、金额放大成视觉焦点（天数 40px / 补零两位）
4. **反转块** —— 黑底白字、黄底黑字，是全站最强的视觉锚点

## 2. 色彩

### 2.1 色板

| 用途 | 值 | 说明 |
|---|---|---|
| 页面底色 | `#FFFFFF` | 纯白。杂志印在白纸上 |
| 下沉底 | `#F4F4F4` | 进度区、代码块、zebra |
| 黑底块 | `#111111` | 反转区、表格表头 |
| 文字（主） | `#111111` | |
| 文字（次） | `#555555` | 所有辅助文字 |
| 文字（禁用） | `#8A8A8A` | **仅非文本 / 禁用态**（3.5:1，不得承载正文） |
| **红（承载文字）** | `#C1121F` | 链接、主按钮、序号方块 |
| **红（纯装饰）** | `#E63946` | 色条、描边、指示点。**不承载任何文字** |
| **黄（高亮底）** | `#FFD60A` | 配黑字使用 |
| 强分隔线 | `#111111` | 2px 黑线 |
| 弱分隔线 | `#DDDDDD` | 表格行、细边 |

### 2.2 对比度（已按 WCAG 2.1 公式核算）

| 组合 | 对比度 | 结论 |
|---|---|---|
| 主文字 `#111` on 白 | **18.9 : 1** | AAA |
| 次文字 `#555` on 白 | **7.5 : 1** | AAA |
| 红 `#C1121F` on 白 | **6.2 : 1** | AA ✓ |
| 白字 on 红 `#C1121F` | **6.2 : 1** | AA ✓ |
| 黑字 on 黄 `#FFD60A` | **14.9 : 1** | AAA ✓ |
| 禁用 `#8A8A8A` on 白 | 3.5 : 1 | ✗ 仅非文本 |
| ⚠️ 白字 on 亮红 `#E63946` | **4.2 : 1** | ✗ 不到 AA |

**最后一行是这个配色最容易踩的坑**：`#E63946` 是很好看的红，但直接拿来当按钮底配白字只有 4.2:1。
所以它被限定为**纯装饰**（色条、描边），任何承载文字的地方一律用 `#C1121F`。

### 2.3 色彩纪律（硬约束）

红黄配色在表单和表格上极容易失控。约束如下：

- 彩色**只用于版面元素**：色块、色条、序号方块、状态标记
- 表单控件、表格、正文一律保持黑 / 白 / 灰，**不参与配色**
- 全站彩色元素合计不超过 3 类，超出的必须去掉

### 2.4 语义色

| 语义 | 值 | on 白 |
|---|---|---|
| 成功 | `#1A7F37` | 5.1 : 1 |
| 警告 | `#9A6700` | 4.9 : 1 |
| 错误 | `#C1121F` | 6.2 : 1 |
| 信息 | `#0969DA` | 5.2 : 1 |

## 3. 字体

```css
--font-display: -apple-system, 'PingFang SC', 'Microsoft YaHei', ... sans-serif;
--font-sans:    （同上）
--font-serif:   Georgia, 'Songti SC', 'Times New Roman', serif;
--font-num:     'SF Mono', 'Cascadia Mono', Consolas, monospace;
```

- **display 用无衬线粗体** —— 呼应杂志封面的粗黑标题。中文字重上限是 700，
  所以分量靠"字号 + 700 + 负字距"三件事一起做
- **衬线只用于引言、注解、编辑性文字**（`group-note`、`masthead-sub`），增加"出版物"的味道
- 不引入自定义字体（成本与收益不成比例）；中文字体沿用系统栈

### 字阶

| 名称 | 值 |
|---|---|
| display | `clamp(36px, 7vw, 64px)` / 700 / `-0.02em` |
| h1 | 32px / 700 / `-0.01em` |
| h2 | 22px / 700 |
| h3 | 17px / 600 |
| body | 15px / 400 / 行高 1.7 |
| caption | 13px |
| label | 11px / **700 / `0.1em` 宽字距 / 大写** |

display 64 ÷ body 15 = **4.3×**（符合杂志的强对比）。

`.u-label`（宽字距大写小标签）是这个方向最重要的文字处理——区块标题、表头、字段名全部走它。

## 4. 间距 / 圆角 / 阴影 / 动效

```css
/* 间距：严格 8pt */
--space-1..8: 4 / 8 / 16 / 24 / 32 / 48 / 64 / 96px
--pad-page: 48px   --pad-page-md: 32px   --pad-page-sm: 20px
--measure: 720px   --container: 1160px

/* 圆角：全部方角 */
--radius-sm: 0   --radius-md: 0   --radius-pill: 0

/* 阴影：只给真正浮起来的层 */
--shadow-overlay: 0 12px 40px rgba(0, 0, 0, 0.18)

/* 动效：干脆 */
--dur-fast: 140ms   --dur-base: 220ms   --dur-slow: 380ms
--ease-out: cubic-bezier(0.2, 0, 0, 1)
```

**方角是这个方向最直接的切割**——圆角会立刻把气质拉回"圆角 SaaS"。

## 5. 组件语言

| 组件 | 做法 |
|---|---|
| 主按钮 | 实心红 `#C1121F` + 白字 + 方角。在反转底上改用**黄底黑字**（红配黑会糊） |
| 次按钮 | 白底 + 1px 黑框；hover **反转成黑底白字**（替代"加阴影"表达 hover） |
| 文字按钮 | 红字 + 下划线，与正文链接一致 |
| 危险按钮 | 黑框红字 → hover 反转成红底白字 |
| 输入控件 | 白底 + 1px 黑描边 + 方角；hover 变红框；聚焦红色描边（用 box-shadow 叠加，避免盒子高度跳动） |
| 卡片 | **不封边**，只用一条 2px 黑顶线 |
| 表格 | 表头**黑底白字**（全站唯一大面积黑块）+ 行间 1px 浅线，无竖线 |
| 标签 | 方角 + 1px 黑描边 + 大写宽字距；状态类用**黄底黑字** |
| 折叠面板 | 2px 黑顶线 + 1px 细行线 |
| 浮层 | 方角 + 1px 黑边 + `--shadow-overlay`（唯一允许阴影的地方） |
| 状态标记 | 用**方块**而不是圆点 |

## 6. 知识库页的信息架构简化

原结构是 **5 个平铺区块**：环境状态（还拆成 3 张卡）／ 检索调试 ／ 数据源 ／ 灌库 ／ 说明。
问题是首屏被三张状态卡占满，而数据源 / 灌库 / 说明是"偶尔用一次"的东西却占了约 60% 的页面。

**改成：**

```
[红色短线]
知识库
说明文字

● 正常 · POI 1,750 · 攻略 30 块 · [生成时未启用]        [详情] [刷新]   ← 一行状态条
───────────────────────────────────────────────────────────
检索调试（主体）
───────────────────────────────────────────────────────────
▸ 维护（折叠：灌库 + 数据源）
───────────────────────────────────────────────────────────
这套知识库是怎么工作的？                                              ← 弹窗
```

三处合并：
1. **3 张状态卡 → 1 行状态条**，「详情」展开才显示可用性明细、修复指引、开关说明
2. **数据源并入灌库预览** —— 预览接口本来就在统计这些数字（按城市分布、每篇切几块），
   独立展示是重复。合并后「试检索」按钮也一并搬过去
3. **说明收成底部一行链接** → 弹窗

净效果：**5 块 → 2 个可见单元 + 1 个折叠**，关键信息一个没少。

## 7. 分页推进的工程约束

改造是分页进行的，未改造的页面仍引用旧变量名。因此 `tokens.css` 保留了一整块
`@deprecated` 过渡别名（`--sp-N`、`--border-1/2`、`--bg-card`、`--brand-*`、
`--radius-lg/xl/pill`、`--shadow-N`、`--fw-bold` 等），值已映射到新体系最接近的档位。

**没有这层映射，未改造的页面会明显坏掉**——最典型的是 `--border-*` 改名成 `--line-*` 后，
`border: 1px solid var(--border-1)` 会拿到无效值，边框退化成 `currentColor`（深色描边）。

已用脚本全量核对：85 个 `var(--x)` 引用全部有定义。四个页面全改完后，整个区块可删。
